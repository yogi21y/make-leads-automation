# אוטומציית Make: פניות מטופס אל Airtable

תרחיש (Scenario) ב-Make שמקבל פנייה חדשה מטופס, בודק אותה, ורושם אותה בטבלת הפניות ב-Airtable. הפנייה מופיעה אחר כך בדאשבורד לניהול לידים של עסק צילום, בלחיצה על "טען פניות מחדש".

זה פרויקט לימוד, ונבנה במסגרת קורס מטמיעי AI (שיעור 5). כל הנתונים בו מדומים.

## איך זה עובד

```
טופס  ->  ווב-הוק (Webhook)  ->  נתב (Router)  ->  יצירת רשומה ב-Airtable  ->  תשובה לשולח
                                     |
                                     +-> פנייה לא תקינה  ->  תשובה 400
                                     +-> מפתח שגוי       ->  תשובה 403
```

1. **ווב-הוק (Custom webhook):** כתובת אינטרנט ש-Make יוצר. כשטופס שולח אליה בקשה, התרחיש מתחיל מיד, בלי בדיקה חוזרת כל כמה דקות.
2. **נתב (Router):** שלושה מסלולים. מפתח שגוי, פנייה תקינה, פנייה לא תקינה.
3. **יצירת רשומה (Airtable Create a record):** נוצרת שורה בטבלה `leads`, עם שלב הטיפול "פנייה חדשה".
4. **תשובה (Webhook response):** חוזרת לשולח עם קוד ו-JSON קצר.

## מה הווב-הוק מקבל

בקשה מסוג POST עם JSON. שמות השדות זהים לעמודות הטבלה.

| שדה | חובה | הערה |
|---|---|---|
| `Name` | כן | |
| `Phone` | כן | |
| `ShootType` | כן | אחד מ: סטילס, וידאו, סטילס ווידאו |
| `Description`, `ShootDate`, `FollowUpDate`, `Notes` | לא | תאריכים בפורמט `YYYY-MM-DD` |
| `Amount` | לא | מספר שאינו שלילי |
| `secret` | כן | מפתח סודי, ראו בהמשך |

דוגמה (נתוני דמה):

```json
{
  "Name": "לקוח לדוגמה",
  "Phone": "050-0000000",
  "ShootType": "סטילס",
  "Amount": 1500,
  "secret": "YOUR_SECRET"
}
```

## מה התרחיש מחזיר

| מצב | קוד | נוצרת שורה |
|---|---|---|
| פנייה תקינה | 200 | כן |
| חסר שם, טלפון או סוג צילום, סוג צילום לא חוקי, או סכום שלילי | 400, עם הודעה בעברית שמסבירה מה חסר | לא |
| מפתח סודי שגוי או חסר | 403 | לא |

## בדיקות שבוצעו

נשלחו חמש בקשות עם נתוני דמה. כולן החזירו את הקוד הצפוי, והפנייה התקינה בלבד יצרה שורה בטבלה. פירוט ב-[tests.md](tests.md).

## איך מייבאים ל-Make

1. ב-Make: יוצרים תרחיש חדש, ובתפריט `...` בוחרים **Import Blueprint**.
2. בוחרים את הקובץ `leads-intake-webhook-to-airtable.blueprint.json`.
3. **מחליפים את הכתובת (Webhook):** בוחרים ווב-הוק משלכם, או יוצרים חדש.
4. **מחליפים את החיבור (Connection):** מחברים את חשבון ה-Airtable שלכם.
5. **מחליפים את הטבלה:** בוחרים את הבסיס והטבלה שלכם, ומוודאים שהמיפוי של השדות נשאר נכון.
6. **מגדירים מפתח סודי:** בשלושת המסננים (Filters) מחליפים את `REPLACE_WITH_YOUR_SECRET` במפתח שאתם בוחרים. מפתח אקראי ארוך עדיף.

### מבנה הטבלה הדרוש ב-Airtable

| עמודה | סוג |
|---|---|
| `Name` | טקסט קצר |
| `Phone` | טלפון או טקסט קצר |
| `ShootType` | בחירה אחת מרשימה: סטילס, וידאו, סטילס ווידאו |
| `Description` | טקסט ארוך |
| `ShootDate`, `FollowUpDate` | תאריך |
| `Amount` | מספר |
| `Notes` | טקסט ארוך |
| `Status` | בחירה אחת מרשימה: פנייה חדשה, שיחה עם לקוח, נשלחה הצעת מחיר, נסגרה עסקה, לא התקדמה |

## אבטחה

- קובץ ה-Blueprint **לא כולל** מפתחות, טוקנים או כתובת ווב-הוק. המפתח הסודי הוחלף במחרוזת `REPLACE_WITH_YOUR_SECRET`.
- המזהים בקובץ (חיבור, ווב-הוק, בסיס וטבלה) שייכים לחשבון המקורי ולא יעבדו בחשבון אחר. יש להחליף אותם בייבוא.
- כל מי שמכיר את כתובת הווב-הוק יכול לשלוח אליה בקשות. לכן התרחיש בודק מפתח סודי ודוחה בקשות בלעדיו.

## מגבלות

- **לא בודק פורמט תאריך.** תאריך לא תקין ייכשל ב-Airtable.
- **לא מזהה פניות כפולות.**
- **טופס אמיתי לא נבנה.** הבדיקות נעשו בשליחת בקשות דמה.
- **שליחת עברית משורת הפקודה (Git Bash, curl) משבשת את הקידוד.** לבדיקות מומלץ JSON עם רצפי `\u`, או PowerShell. טופס בדפדפן שולח UTF-8 תקין.
- **חשבון Free של Make** מוגבל ל-1,000 קרדיטים בחודש, וכל בדיקה צורכת קרדיטים.
- **חשבון הניסיון של Airtable** מסתיים בסביבות 30.11.2026. לפני שימוש יש לוודא שחיבור ה-API ממשיך לעבוד.
